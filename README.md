# 망자의 계약 (Pact of the Fallen)

멸망한 왕국의 지하 묘소. 계약자인 당신은 **영혼석**으로 쓰러진 영웅들의 혼을 불러내(가챠) 계약하고, 그들의 몸을 빌려 던전 최심부의 「끝없는 왕」을 쓰러뜨려야 합니다.
왕을 쓰러뜨리면 후속 스토리 **「잿빛 성좌」 → 「핏빛 왕관」 → 「태초의 계약」**이 차례로 열립니다 (스토리 4개 × 6스테이지).

2D 횡스크롤 **핵앤슬래시 로그라이트 + 수집형 가챠** (싱글 플레이 전용, 현실 결제 없음).
전투 중 두 영웅을 바꿔 끼며 싸우는 손맛, 매 런 달라지는 영웅·무기·유물 조합, 그리고 런에서 번 재화로 돌리는 가챠가 핵심입니다.

- Vite + TypeScript(strict) + Canvas 2D, **외부 런타임 라이브러리·이미지·사운드 파일 0개**
- 모든 그래픽은 코드로 그린 픽셀 아트(오프스크린 캔버스 캐시), 모든 사운드와 음악은 WebAudio 절차 합성
- 내부 해상도 480×270, 정수 배율 확대, 고정 타임스텝 60Hz
- 키보드 + 게임패드, 키 재설정, 자동 저장(localStorage) + JSON 내보내기/가져오기

## 실행

```bash
npm install && npm run dev     # http://localhost:5173
```

## 계정과 저장

게임을 켜면 **로그인 / 회원가입** 화면이 먼저 나옵니다. 게임 전용 아이디(영문 소문자·숫자·_ 4~16자)와 비밀번호(6자 이상)로 가입하며, 다음부터는 자동 로그인됩니다. 타이틀 메뉴의 **로그아웃**으로 다른 계정으로 바꿀 수 있습니다.

- 계정마다 기록(영웅·무기·재화·가챠 천장·스토리 진행·업적·설정)이 따로 저장됩니다.
- **런 이어하기**: 방에 들어갈 때·방을 정화했을 때·보상을 받았을 때 진행 중인 런이 저장됩니다. 런 도중 창을 닫거나 새로고침해도 타이틀의 **런 이어하기**로 마지막으로 들어간 방부터 계속합니다(정화한 방은 정화된 채로, 열어 본 상자·제단은 사용한 채로). 전투 도중에 나가면 그 방에 들어온 순간부터 다시 시작합니다.
- 계정이 생기기 전에 이 브라우저에서 하던 기록은 처음 만드는 계정으로 자동으로 옮겨집니다.

### 저장 위치

| 모드 | 조건 | 저장 위치 | 다른 기기 |
|---|---|---|---|
| 온라인 계정 (**현재 배포본**) | `src/data/firebase.ts`에 Firebase `apiKey`·`projectId` 입력 — 프로젝트 `contract-d6cf3` 연결됨 | Firebase Authentication(이메일/비밀번호) + Firestore `saves/{uid}` | 같은 아이디로 어디서든 이어서 플레이 |
| 이 기기 전용 계정 | 설정이 비어 있을 때, 또는 localStorage `pact_force_local`=`1` (E2E가 사용) | 이 브라우저 localStorage (비밀번호는 PBKDF2 해시) | 불가 — 설정의 내보내기/가져오기로 옮김 |

Firebase SDK 없이 REST API(`identitytoolkit`, `securetoken`, `firestore`)로 직접 통신하므로 외부 런타임 라이브러리는 여전히 0개입니다. 아이디는 내부적으로 `아이디@pact-of-the-fallen.game` 형식의 가짜 이메일로 바뀌며 메일은 보내지 않습니다. 기록은 로컬에 즉시 캐시되고 클라우드에는 2초씩 모아서, 창을 닫을 때는 바로 보냅니다. 로그인할 때 로컬 캐시와 클라우드 중 더 최근 기록을 씁니다.

### Firebase 연결 방법

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 프로젝트를 만들고 **웹 앱**을 추가
2. **Authentication → 로그인 방법 → 이메일/비밀번호** 사용 설정
3. **Firestore Database** 만들기 → **규칙**에 아래를 붙여넣고 게시

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /saves/{uid} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }
     }
   }
   ```
4. 프로젝트 설정 → 일반 → 내 앱의 `apiKey`, `projectId`를 `src/data/firebase.ts`에 입력 후 `npm run build:pages`
5. (권장) Authentication → 설정 → **승인된 도메인**에 `xkv7.github.io` 추가

`apiKey`는 웹앱에 원래 공개되는 값이고, 다른 사람의 기록을 읽거나 쓰지 못하게 막는 것은 3번의 규칙입니다.

기본 배치(설정 → 키 재설정에서 개별 변경 가능, 이전 **방향키 배치** 프리셋도 제공)

| 점프 (2단 점프) | W / Space | A |
| 기본 공격 (콤보) | J | X |
| 대시 (짧은 무적, 공중 1회) | Shift (좌·우) | B / RT |
| 스킬 1 / 스킬 2 | E / R | LB / RB |
| 교대 (영웅 교체 + 교대 공격) | G | Y |
| 상호작용 | F | RS |
| 소모 아이템 | K | LT |
| 빌드 확인 | Tab | Back |
| 일시정지 | Esc | Start |

- **콤보**: 공격 연타(영웅마다 3~5타). 마지막 타격은 피니시(히트스톱·충격 강화)
- **대시 캔슬**: 공격 중 언제든 대시로 끊기 / 대시 중·직후 공격 = **대시 공격**
- **공중**: 2단 점프 + 공중 대시 1회, 공중 공격. 벽 짚기는 없음
- **발판 내려가기**: S(아래) + Space(점프)
- **교대**: 대기 영웅이 고유 교대 공격과 함께 등장. 적중 시 짧은 슬로모션
- 메뉴: W/S/A/D 또는 방향키로 이동, J·F·Space·Enter로 결정, Esc·Backspace로 뒤로. 도감 탭 전환은 E/R
- 방향키 프리셋: ←→↑↓ 이동 · C 점프 · X 공격 · Z 대시 · A/S 스킬 · D 교대 · F 상호작용 · Q 아이템

### 개발자용 디버그 모드 (게임 내 조작법 화면에는 표시하지 않음)

**Ctrl + Shift + ` + Space** 로 켜고 끕니다. 디버그 모드에서만, 상단 숫자키·숫자 패드 모두: **1** 무적 · **2** 영혼석+1600/영혼 결정+1000 · **3** 방의 적 전멸 · **4** 보스방 이동 · **5** 체력·쿨타임 회복. 

디버그 모드에서는 **출정 편성**의 영웅·무기 선택 창에 보유하지 않은 영웅·무기까지 모두 나와, 원하는 캐릭터로 바로 테스트할 수 있습니다(레벨 1·재련 1, 기록에는 추가되지 않음. 디버그를 끄면 편성이 보유한 것으로 돌아갑니다).

디버그 모드에서 계약의 제단 **별의 인도**(픽업) 배너에 `픽업 선택 (P)` 버튼이 나타납니다. P 키나 클릭으로 열어 ★5 픽업 1명·★4 픽업 2명을 직접 고르고 **적용**하면, 런 횟수에 따른 자동 교체 대신 지정한 픽업이 유지됩니다(저장됨). **자동 로테이션 복귀**로 원래대로 돌아갑니다. 천장 카운트는 바뀌지 않습니다.

히트박스(초록=공격, 파랑=플레이어, 주황=적, 분홍=투사체)와 FPS·엔티티 수를 표시합니다.

## 게임 흐름

1. **타이틀** — 배경에서 무작위 영웅 둘이 자동 전투하는 데모. 시작/이어하기/설정/조작법
2. **계약의 성소(거점)** — 걸어 다니는 허브. 계약의 제단(가챠) · 도감 · 출정의 문/편성 · 영웅 육성 · 영구 강화(10종) · 업적 비석 · 훈련용 허수아비(DPS 측정)
3. **첫 계약** — 무료 10연, ★4 이상 확정
4. **편성** — 보유 영웅 2명 + 무기 1개 + **스토리 선택** (+ 해금 시 저주 단계)
5. **런** — 스토리마다 6스테이지(스토리 1은 5장 + 선택 6장) × 방 7~10개. 후속 스토리는 처음 출정할 때 이야기 화면이 나옵니다. 방을 정화하면 다음 방 문 2~3개가 열리고 문 위에 보상 아이콘이 표시됩니다. 첫 런은 조작 안내 표지판이 있는 훈련의 방으로 시작합니다.
6. **결과** — 도달 위치, 처치 수, 피해량, 최대 콤보, 획득 영혼석/영혼 결정, 최종 빌드, 사망 원인 → 성소로

### 스토리

| 스토리 | 이름 | 목표 | 적·보스 배율 | 해금 |
|---|---|---|---|---|
| 1 | 망자의 계약 | 끝없는 왕을 쓰러뜨려라 (6장 망각의 심연은 선택 진엔딩) | 체력 ×1 · 공격 ×1 | 처음부터 |
| 2 | 잿빛 성좌 | 혼을 삼키는 별을 꺼뜨려라 | 체력 ×1.5 · 공격 ×1.3 | 스토리 1 완수 |

스토리 배율은 진행 단계 배율(1장 ×1 → 6장 ×2.9) 위에 곱해집니다. 예: 스토리 2의 1장 적 ≈ 스토리 1의 2장, 스토리 2의 6장 ≈ 스토리 1 6장의 1.5배.

스토리를 처음 완수하면 엔딩 이야기와 함께 다음 스토리가 열리고, 출정 편성의 **스토리** 칸에서 고를 수 있습니다. 스토리 완수 업적(2·3·4) 보상 2000/3000/4000 영혼석.

### 난이도와 보스 공격

- 모든 일반 적: 체력·공격력 **1.5배**, 공격 후 대기 20% 단축, 이동 12% 가속 (`ENEMY_TUNE`). 방 깊이에 따른 강화 3.5% → 5%, 방당 적 수 +1
- 보스: 체력·공격력 **1.5배** (`BOSS_TUNE`), **끝없는 왕 3배, 망각 4배**, 각 스토리의 최종 보스 3배. 패턴 사이 대기 시간 단축
- **동시 스킬**: 보스는 주 패턴과 함께 원거리·장판 패턴을 보조로 겹쳐 쓴다 (1페이즈 최대 1개, 2페이즈 이후 최대 2개)
- **즉사기**: 끝없는 왕 「왕의 참수」(바닥 높이를 가르는 칼날 — 판정 순간 땅에 서 있으면 즉사, 뛰어오르거나 발판 위로), 망각 「망각의 선고」(화면 전체가 지워지고 「기억의 빛」 안에만 살아남음) — 2페이즈부터, 15초 재사용 대기, 3·2·1 카운트다운. 체력·보호막·무적을 무시하지만 부활 효과는 적용
- **예고와 판정 일치**: 보스 몸의 빨간 번쩍임은 판정 직전 구간에만 켜지고 판정 프레임에 꺼짐. 바닥·기둥 예고는 사라지는 순간 피해. 낙하 공격은 예고 위치에 정확히 떨어지고, 점프·순간이동 착지 예고는 착지 순간까지 유지

### 데이터 주도 설계

- **액션 DSL** (`ActionDef`): 모든 기본 공격·공중/대시 공격·스킬·교대 공격은 길이·캔슬 프레임·이동·무적 구간·포즈 타임라인과 프레임별 이벤트(`hit` `proj` `field` `summon` `buff` `shield` `timestop` `counter` `tp` `meteor` `nova` `chain` `plunge` `fx` `sfx` …)로만 기술됩니다. 새 영웅은 `src/data/characters.ts`에 데이터를 추가하는 것만으로 만들 수 있습니다.
- **효과 훅** (`Effect`): 유물·무기·문장·패시브·각성은 모두 같은 형식 — 상시 스탯 / 조건부 스탯(`lowHp` `shielded` `comboHigh` …) / 플래그(`burnSpread` `bleedRupture` `revive` …) / 트리거(`hit` `crit` `finisher` `kill` `dash` `swap` `swapHit` `skill` `hurt` `roomStart` `interval` `parry` …) → 프리미티브(`status` `explode` `chain` `heal` `shield` `proj` `buff` `cdr` `echo` `wave` `strike` `nova` `slowTime` `meteor` `summon`). 무기 재련은 효과 수치를 일괄 스케일링합니다.
- **엔티티**: `Body`(AABB·속도·접지) 위에 플레이어/적/보스가 각자 상태 머신을 가집니다. 플레이어: normal/act/dash/hurt/dead + 액션 실행기. 적: spawn/idle/move/wind(예고)/atk/recover/hurt/stun/skill. 보스: 페이즈 → 패턴 풀 → 프레임 타임라인 패턴.
- **장면 상태 머신**: Title → Intro → Hub ⇄ (Gacha · Codex · Loadout · Growth · Upgrade · Ach · Settings · Controls) → Run(+오버레이: 일시정지·빌드·유물 선택·상점·제단·무기고·휴식·이벤트) → Result → Hub
- **저장**: 계정별(기기 전용 localStorage 또는 Firebase Firestore) JSON — 재화, 보유 영웅(레벨·각성), 무기(재련), 배너별 뽑기 기록, 스토리 해금·완수, 영구 강화, 업적, 저주, 통계, 설정·키 설정. 모든 접근은 try/catch이며 실패해도 메모리 상태로 계속 동작. 불러올 때 누락 필드를 보정합니다.

### 데미지 공식

`피해 = 기본 공격력 × (1+공격%) × 기술 배율 × (1+피해 증가 합) × 치명(1.5+치피) × (1−방어) × 감전 1.15 × 변동(0.95~1.05)`
기본 공격력 = 영웅 공격력 × (1 + 0.06×(레벨−1)) + 무기 공격력, 각성 단계당 +3%. 받는 피해 = 원본 × (1+받는 피해%) × (1 + 0.12×저주 단계).

## E2E 테스트

`npm run e2e`는 Vite 서버를 띄우고 헤드리스 Chromium으로 다음을 실제 키 입력으로 진행합니다.
타이틀 → 인트로 → 거점 → 계약의 제단에서 첫 무료 10연 → 출정의 문(편성) → 런 시작 → 이동/공격/점프/대시/교대/스킬/빌드 화면 → Ctrl+Shift+`+Space 디버그 + 4 치트로 보스방 이동 → 보스전.
콘솔 에러가 하나라도 있으면 실패하며, 주요 장면 스크린샷을 `screenshots/`에 저장합니다.
(Playwright가 브라우저를 찾지 못하면 `npx playwright install chromium`)

### 개발용 스크립트

- `node scripts/soak.mjs <url> <런 수> [스크린샷 폴더] [시작 번호]` — 모든 영웅·무기 조합을 바꿔 가며 런 끝까지(분기·6장 포함) 자동 진행하는 소크 테스트(무적). 런타임 오류를 수집
- `node scripts/bot.mjs <url> <영웅1,영웅2> <레벨>` — 단순 AI로 무적 없이 진행하며 방별 체력 변화를 기록하는 밸런스 봇
- `node scripts/probe.mjs <url> <출력폴더> <단계...>` — 키 입력 시퀀스 + 스크린샷 탐색 도구
